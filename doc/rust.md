# Rust

rust-analyzer driven by [rustaceanvim](https://github.com/mrcjkb/rustaceanvim),
Clippy on save, working debugging, and `Cargo.toml` as a first-class file.

---

## Why rustaceanvim replaced the plain setup

The old `vim.lsp.config("rust_analyzer", …)` block in `lspconfig.lua` is gone.
rustaceanvim starts and configures rust-analyzer itself, so leaving both in
place would put **two rust-analyzer clients on every Rust buffer** — doubled
memory, doubled `cargo check`, duplicated diagnostics.

That is not hypothetical: Mason's `automatic_enable` starts every installed
server, and `rust-analyzer` is installed there, so it kept auto-starting a
second client even after the lspconfig block was removed. It's now in
`automatic_enable.exclude` in `mason.lua`, next to `omnisharp`.

What rustaceanvim adds beyond a plain LSP client are the rust-analyzer
*extensions* — features exposed over custom LSP methods that a generic client
can't reach: runnables, debuggables, macro expansion, HIR/MIR views and
`rustc --explain`.

> Your old settings never applied. The previous block used all-lowercase keys
> (`inlayhints`, `typehints`, `chaininghints`); rust-analyzer expects
> `inlayHints`, `typeHints`, `chainingHints` and silently ignored the rest.
> Every setting below is correctly cased.

## Keymaps

Buffer-local to Rust files:

| Key | Action |
| --- | --- |
| `<leader>rr` | **Runnables** — pick any `main`, test, bench or example and run it |
| `<leader>rd` | **Debuggables** — same list, but builds and attaches the debugger |
| `<leader>rt` | **Testables** — run the test at or under the cursor |
| `<leader>rm` | Expand the macro under the cursor |
| `<leader>re` | Explain the error under the cursor (`rustc --explain`) |
| `<leader>rD` | Render the full diagnostic, with the pretty rustc rendering |
| `<leader>rc` | Jump to `Cargo.toml` |
| `<leader>ca` | Code actions (rust-analyzer's, which are richer than the LSP default) |
| `K` | Hover **actions** — hover, then act on what's under the cursor |

Everything else is available through `:RustLsp <subcommand>`, which is a
**buffer-local** command created once the client initialises — it won't show up
in `:command` output from a non-Rust buffer. `:RustAnalyzer` (global) restarts,
stops and starts the server.

On `Cargo.toml`, `crates.nvim` takes over the same prefix:

| Key | Action |
| --- | --- |
| `K` / `<leader>rc` | Crate details popup |
| `<leader>rv` | Available versions |
| `<leader>rf` | Available features |
| `<leader>ru` | Update this crate |
| `<leader>rU` | Upgrade this crate (allows major bumps) |
| `<leader>rA` | Upgrade every crate |

Latest versions show as virtual text next to each dependency.

## Settings that matter

In `lua/engine/plugins/rust.lua`:

| Setting | Value | Why |
| --- | --- | --- |
| `check.command` | `clippy` | Clippy instead of plain `cargo check` on save. The single biggest quality win — you get lint suggestions, not just type errors. |
| `check.extraArgs` | `--no-deps` | Don't lint your dependencies. |
| `cargo.allFeatures` | `true` | Analyse feature-gated code instead of silently ignoring it. |
| `cargo.buildScripts.enable` | `true` | Resolve code generated by `build.rs`. |
| `procMacro.enable` | `true` | Resolve proc-macro output (`#[derive(...)]`, `#[tokio::main]`). |
| `diagnostics.disabled` | `unlinked-file` | Silences the warning on any scratch `.rs` outside a Cargo project. |
| `files.excludeDirs` | `target`, `node_modules`, `.git` | Keeps the index off build output. |

Inlay hints are on: type hints, chaining hints, parameter hints and closing-brace
hints past 25 lines. Lifetime, reborrow and closure-return hints are off — they
are the noisy ones.

### Inlay hints are enabled here, not globally

The shared `LspAttach` handler in `lspconfig.lua` guards inlay hints behind
`server_capabilities.inlayhintprovider`. Lua keys are case-sensitive and the
real key is `inlayHintProvider`, so that branch has never fired for any server.
Rather than repair it — which would switch hints on for every language at once —
each server that wants them opts in through its own `on_attach`. See
[`doc/csharp.md`](csharp.md) for the full list of case-corrupted keys.

## Debugging

`codelldb` is installed via Mason and wired into both rustaceanvim and nvim-dap.

The best entry point is `<leader>rd` (**debuggables**): it builds the target
first, understands test harnesses and workspace members, and picks the right
binary — none of which a hand-written launch config does.

Your existing debugger keys work as usual once stopped:

| Key | Action |
| --- | --- |
| `<leader>db` | Toggle breakpoint |
| `<leader>dc` | Continue |
| `<leader>ds` / `<leader>di` / `<leader>do` | Step over / into / out |
| `<leader>dt` | Terminate |

> **This also fixed C and C++ debugging.** `dap.lua` looked for an adapter with
> `vim.fn.exepath()` only, but Mason installs into `~/.local/share/nvim/mason/bin`,
> which is deliberately *not* on `PATH`. So it never found codelldb and printed
> `No C/C++ DAP adapter found` on every single startup. It now checks Mason's
> bin directory too.

## Formatting

`rustfmt` runs on save. conform reads the **edition out of `Cargo.toml`**
rather than defaulting to 2015 — which matters, because on the 2015 edition
rustfmt mangles `async`/`await` and `dyn`.

`rustfmt.toml` / `.rustfmt.toml` in the project root is honoured.

`ftplugin/rust.vim` sets 4-space indentation to match.

## Troubleshooting

**Two clients, or duplicated diagnostics.** Check with
`:lua =#vim.lsp.get_clients({bufnr=0})` — it should be `1`. If it's 2, something
re-enabled `rust_analyzer`; check `automatic_enable.exclude` in `mason.lua`.

**`:RustLsp` is not an editor command.** It's buffer-local and only exists after
the client initialises. Wait for rust-analyzer to finish loading, and make sure
you're in a `.rs` buffer.

**No diagnostics in a workspace member.** rust-analyzer needs the crate to be
reachable from the root `Cargo.toml`'s workspace members.

**Clippy never runs.** `rustup component add clippy`. Verify with
`:checkhealth rustaceanvim`.

**Proc macros unresolved.** Usually a toolchain mismatch — rust-analyzer must be
built against the same compiler. `rustup update` and restart with
`:RustAnalyzer restart`.
